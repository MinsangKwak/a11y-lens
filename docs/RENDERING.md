# 초기 렌더링과 3G 검증

2026-11-05 기준 `fix/startup-rendering` 브랜치의 개선 기록입니다. 기준 코드는 `dev` 커밋 `0ab0e7e`이며, 초기 표시와 배치 갱신을 개선하고 검사 범위·판정 기준은 유지했습니다.

## 원인과 변경

| 확인한 구조 | 변경 |
| --- | --- |
| electron-vite의 renderer 기본 설정이 비압축이어서 초기 JS가 659,851바이트 | renderer의 esbuild 압축과 CSS 압축을 명시 |
| 개발 모드에서 JS 모듈이 실행되어야 CSS를 삽입 | HTML의 stylesheet 링크로 CSS를 먼저 발견·적용 |
| 초기 HTML의 root가 비어 있어 React와 로그인 상태 확인까지 콘텐츠가 없음 | React 대기 화면과 같은 제목·간격의 HTML 시작 화면 제공 |
| 창의 초기 바탕이 공통 CSS와 다를 수 있음 | Electron `backgroundColor`를 기존 바탕색과 일치 |
| resize와 ResizeObserver가 각각 좌표를 읽고 IPC 전송 | requestAnimationFrame으로 측정을 합치고 동일한 정수 좌표는 재전송하지 않음 |
| 창은 preload의 `index.js`를 가리키지만 빌드 산출물은 `index.mjs` | 실제 산출물 경로로 수정하고 시작 경로 회귀 추가 |

CSS 원본은 약 5KB였으며 외부 폰트·아이콘·이미지 다운로드는 없었습니다. 화면 디자인을 줄이거나 검사 대상 사이트의 CSS를 바꾸지 않았습니다. 검사 함수가 격리 월드로 전달되는 메인 프로세스의 엔진 코드는 압축하지 않습니다.

## 동일 조건으로 3회 비교

Electron의 렌더러 산출물을 로컬 HTTP 서버에서 제공하고 Chromium의 네트워크·CPU 제한으로 비교했습니다. 일반 배포 앱의 `file://` 자원이 3G로 다운로드된다는 뜻은 아닙니다. 느린 자원 로딩과 개발 서버의 초기 표시를 검증하기 위한 재현입니다. 인증·IPC는 모의 객체이며 실제 OAuth나 대상 사이트의 속도를 측정한 결과는 아닙니다.

| 조건 | 값 |
| --- | --- |
| 다운로드·업로드 | 각각 400kbps |
| 지연 | 400ms |
| CPU | 4배 느리게 제한 |
| 캐시 | 비활성, 매회 새 브라우저 컨텍스트 |
| 화면 | 1440 × 940 |
| 전송 | 두 버전 모두 압축 전송 없이 원본 파일 제공 |
| 반복 | 변경 전·후를 번갈아 각각 3회 |

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| JavaScript 파일 | 659,851바이트 | 233,600바이트 |
| CSS 파일 | 5,472바이트 | 3,857바이트 |
| 첫 콘텐츠 표시 FCP 중앙값 | 14.50초 | 1.06초 |
| 로그인 버튼 준비 중앙값 | 14.71초 | 6.05초 |
| CLS | 3회 모두 0 | 3회 모두 0 |

첫 콘텐츠 표시는 시작 안내 화면을 뜻합니다. 로그인 버튼이 동작할 수 있게 되는 시점과 구분했습니다. JS 파일은 약 65% 줄었고 로그인 버튼 준비는 이번 환경의 중앙값 기준 약 59% 짧아졌습니다. 실제 기기·캐시·서버의 전송 압축·네트워크에 따라 값은 달라집니다.

원본 수치는 [rendering-benchmark.json](rendering-benchmark.json)에 있습니다.

```bash
pnpm -r build
node packages/desktop/test/benchmark-renderer.mjs 변경전_renderer폴더 packages/desktop/out/renderer 결과.json
```

기본 브라우저 대신 설치된 Chromium을 검증에 사용하려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`를 지정합니다. CI는 고정된 Playwright 버전의 기본 브라우저를 사용합니다.

## 회귀 검사

기존 엔진·CLI·데스크톱 검사 43건을 유지하고, 첫 창의 바탕·preload 경로 검사 1건을 더했습니다. 별도 브라우저 회귀 7건도 같은 CI 작업에서 실행합니다.

| 추가 브라우저 검사 | 확인 내용 |
| --- | --- |
| JS 응답 지연 | JS 응답을 막아도 스타일이 적용된 시작 안내가 보이며 React 전환 시 제목 위치 유지 |
| 로그인 대기·키보드 | 360px 화면, 줄어든 동작 설정, 키보드 실행과 대기 중 버튼 크기 유지 |
| 배치 변경 | 한 프레임에서 100회 resize와 ResizeObserver가 발생해도 좌표 전송 1회 |
| 배치 유지 | 같은 좌표의 resize 100회에 IPC 재전송 0회 |
| 로그아웃 | 대상 뷰 숨김, 이전 감시와 예약 프레임 해제 |
| 자원 예산 | JS 합계 250KB 미만, CSS 합계 6KB 미만, preload 산출물 존재 |
| 프로젝트 선택 | 네이티브 선택·키보드·포커스와 최소 44px 높이 유지 |

```bash
pnpm -r build
pnpm typecheck
pnpm test
pnpm --filter @a11y-lens/desktop test:render
```

주기적으로 여러 번 3G를 측정하는 벤치마크는 수동 비교 도구입니다. CI에서는 네트워크 응답을 제어하는 브라우저 회귀로 같은 실패 조건을 재현해 검사 시간을 제한합니다. 실제 Electron 창·로그인·검사 대상 뷰의 플랫폼별 동작은 별도로 확인해야 합니다.
